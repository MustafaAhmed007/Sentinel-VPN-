WireGuard VPS + nftables P2P Port Forwarding

P2P forwarding is powerful because it exposes an inbound service. That makes bounded allocation, ownership, revocation and auditability more important than simply adding a NAT rule.

Control flow

client → authenticated API → lease allocation → nftables rule
                                  ↓
                         WireGuard peer address
                                  ↓
                             P2P service

Lease requirements

  • Use a narrow allowed port range.
  • Associate every lease with one peer.
  • Give leases an explicit lifetime.
  • Revoke expired or disconnected leases.
  • Make allocation idempotent where possible.
  • Do not accept arbitrary firewall expressions from clients.

nftables principle

The control plane should generate a small, predictable ruleset from structured state. Clients should request “forward public port X to peer Y,” not submit raw nftables commands.

Security tests

  1. Request a valid lease.
  2. Confirm only the requested port is reachable.
  3. Attempt an unauthorized peer mapping.
  4. Expire the lease and confirm the port closes.
  5. Restart the control plane and verify state handling.
  6. Revoke a peer and confirm forwarding disappears.
