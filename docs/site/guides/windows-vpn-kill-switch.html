Windows VPN Kill Switch: Fail-Closed Design

A real kill switch is a policy system, not a button. The important property is that an unexpected VPN failure cannot silently restore the ordinary network path.

Desired invariant

VPN_NOT_VERIFIED → INTERNET_TRAFFIC = BLOCKED

State machine

Locked → Connecting → Verifying → Connected
   ↑          │            │          │
   └──────────┴────────────┴──────────┘
              any failure

What to block

Block normal outbound traffic at the Windows firewall layer while the VPN is unverified. Permit only the minimum traffic required to establish and maintain the tunnel, plus the explicit WireGuard interface policy.

Do not confuse these signals

  • “WireGuard process is running” is not a secure state.
  • “Interface exists” is not a secure state.
  • “Handshake happened once” is not permanent proof.
  • “Default route changed” is not DNS proof.

Failure tests

  1. Kill the tunnel process.
  2. Disable the network adapter.
  3. Move between Wi-Fi and Ethernet.
  4. Sleep and resume the machine.
  5. Make the VPS endpoint unreachable.
  6. Restart the privileged service.

Every failure path should return to a blocked state until verification succeeds again. See release gates.
