DNS and IPv6 Leak Protection

A VPN can have a healthy WireGuard handshake while DNS queries or IPv6 traffic follow a different path. Treat these as independent verification domains.

Verification matrix

LayerQuestion
HandshakeIs the peer recently reachable?
RouteDoes normal traffic use the expected tunnel?
DNSAre configured resolvers used through the intended path?
IPv6Is IPv6 intentionally tunneled or intentionally blocked?
FirewallCan a physical interface bypass the tunnel?

DNS policy

Apply DNS servers to the intended VPN interface, preserve the user's previous state, and restore it safely on disconnect. Avoid treating a successful configuration command as proof; query and route behavior should be checked.

IPv6 policy

Choose an explicit product policy. Either provide correct IPv6 tunneling and verification or block unintended IPv6 paths while the VPN is active. “We do not support IPv6” is not itself leak protection.

Regression tests

  • DNS query before, during and after connection.
  • IPv4 and IPv6 public-address checks.
  • Network adapter changes.
  • DNS server changes made outside the app.
  • Disconnect and restoration verification.

Use these tests as release evidence rather than marketing claims.
