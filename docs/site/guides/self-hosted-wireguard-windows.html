Self-Hosted WireGuard VPN on Windows

A self-hosted VPN is more than a WireGuard configuration file. The client also needs a trustworthy policy layer that decides when ordinary traffic is allowed.

Reference architecture

React UI → Tauri → authenticated IPC → privileged Rust service
                                      ↓
                          firewall + DNS + routes + WireGuard
                                      ↓
                                  Linux VPS

Separate the trust boundaries

The UI should not directly own firewall or privileged networking operations. A privileged service can enforce policy even when the UI is closed, restarted, or compromised.

Use WireGuard as the data plane

Keep cryptographic transport delegated to WireGuard. Sentinel's value is lifecycle orchestration, policy enforcement, verification, diagnostics, and infrastructure ownership.

Verify before unlocking

  1. Apply fail-closed firewall state.
  2. Start or update the WireGuard tunnel.
  3. Verify a recent handshake.
  4. Verify the expected route.
  5. Apply and verify DNS policy.
  6. Check IPv6 behavior.
  7. Only then mark the connection usable.

Operational checklist

  • Test boot and service restart.
  • Test Wi-Fi to Ethernet and network loss/recovery.
  • Test sleep/wake.
  • Test tunnel endpoint failure.
  • Run DNS and IPv6 leak checks.
  • Verify firewall restoration on disconnect.
